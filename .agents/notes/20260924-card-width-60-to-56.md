# usage/quota 卡片整体宽度 60 → 56 列（窄屏一屏显示；52 列实测不可行）

## 一句话结论
- `internal/planusage` 的 `cardWidth` 与 `internal/usage` 的 `reportWidth` 均由 **60 改为 56**（两卡同宽，差值 0），所有派生态随常量重算：quota 侧 `cardInner` 56→52、`barCells` 51→47、`detailWidth` 38→34、`bodyMax` 54→50、边框 dash 数 `cardWidth-2` 58→54；usage 侧 `reportInner` 56→52、`tableWidth` 56→52、`descMax` 54→50、规则行 dash 58→54。**胶囊几何公式不变**：quota `barCells` 仍是「inner − indent − pct(4) − gap(1)」（随内宽 52 重算得 47），usage `hitCells` **仍为 10**、`hitGap` 1、`pctWidth` 6、`hitWidth` 17、`reqWidth`/`cacheWidth` 仍各 6——usage 侧这几项是既有不变量，没有为腾地方缩水。`modelMaxWidth` **仍为 20**，`claude-sonnet-4` 完整显示，`very-long-model-nam…`（20 列截断）断言继续成立。
- **52 列不可行（实测）**：usage 卡片分组列预算 = `tableWidth − reqWidth − cacheWidth − hitWidth − colGap×(n+2)`；单分组键时 = `reportWidth − 4 − 6 − 6 − 17 − 3 = reportWidth − 36`。要求模型列上限 ≥ 20，则 `reportWidth ≥ 56`。在 52/53/54/55 列实测（把两常量临时改掉后跑 `TestRenderUsageReportGroupColumnBudget` 与 `TestRenderUsageReportModelColumnTruncation`），模型列实际宽度与上限分别塌到 16/17/18/19，`model column cap = 16..19, want 20`、`very-long-model-nam…` 不再出现，即硬约束「`modelMaxWidth` = 20」被破坏；56 列恰好让预算 = 20，全部测试通过。**故在「胶囊 10 格 + 模型名不截断（上限 20）+ 既有不变量全保留」前提下，52..60 的最小可行宽度是 56。**
- 兼容红线**不变**：JSON 输出与 `/admin/quota?format=table` 的 legacy 表格路径（`RenderTable`/`RenderTableAt`/`formatRemain`）逐字未动、CLI flag、SQL 与 store 层、`internal/render` 公共函数（`PadRight`/`PadLeft`/`Truncate`/`CapsuleBar`/`CapsuleLevel`/`CapsuleUsedCells`/`DisplayWidth`）实现未动，填充与截断仍全部走这些公共原语；`quota`/`usage` 两卡最终总宽度相同（56）。

## 背景
- 用户诉求：两张终端表格卡片（quota 的 `RenderCards` 与 usage 的 `RenderUsageReport`）整卡 60 列在手机等窄屏一屏显示不全，希望缩窄到 52 列，同时**不得**牺牲 10 格命中率胶囊与可读的模型名列。
- 两卡自 v0.31.0 起同宽同族（同一 `cardWidth`/`reportWidth` 量级、同一边框词表 `╭─ ├─ ╰─`、同一 `internal/render.CapsuleBar` 原语，见 `20260922-card-symmetric-gutter.md`、`20260922-usage-capsule-report.md`），因此只改一张会造成并列输出时宽度不一致，本轮必须同步。

## 决策
- **quota 侧（`internal/planusage/report.go`）**：`cardWidth = 60 → 56`。派生量全部由常量算出、无硬编码：`cardInner = cardWidth - 4`（52）、`barCells = cardInner - barIndent(0) - pctWidth(4) - barGap(1)`（47）、`detailWidth = cardInner - barIndent - resetWidth(18)`（34）、`bodyMax = cardWidth - prefixW(3) - suffixW(1) - 2`（50）、`joinCard` 底边框 `cardWidth-2`（58→54），`cardTitleLine` 的 `fill` 仍按实测 `DisplayWidth` 重算、不写死 dash 数。`pctWidth`、`barGap`、`barIndent`、`resetWidth` 不变。
- **usage 侧（`internal/usage/report.go`）**：`reportWidth = 60 → 56`，`reportInner = reportWidth - 4`（52），`tableWidth = reportInner`（52），`titleLine` 的 `descMax = reportWidth - prefixW - suffixW - 2`（50）、`fill` 仍按实测 `DisplayWidth` 重算；`reportColumns` 的分组列预算公式不变（只是 `tableWidth` 变小），`reqWidth`/`cacheWidth`/`hitCells`/`hitGap`/`pctWidth`/`hitWidth`/`modelMaxWidth` **全部不变**。`internal/usage/handler.go` 注释里的「60-column」同步为「56-column」。
- **测试只改「宽度变化必然导致的期望值」**：`cardLineWidth` 60→56、`cardBarCells` 51→47（注释里的公式同步）与随之而变的胶囊格数期望（34%→16、50%→24、59%→28、94%→45、12%→6、98/99/100/140%→47，`capsuleLevel(0)` 1→2，平地绿 run（34% 18→16、59%/99% 20→19），dim 剩余 run 20→19）、quota/usage 两张整卡精确串（`TestRenderUsageReportExact`、`TestRenderUsageReportStructure` 的分隔线、`TestHandlerTableFormat`）、注释里的宽度数字说明（52−29−3=20、CJK 键 63 列截到 50、2 分组键 19 列 10/9 等）。**没有**放宽任何既有不变量：模型列上限断言仍 `!= modelMaxWidth`（20）、多分组键列数/预算填充断言（`TestReportColumnsFillTheTableArea`、`TestRenderUsageReportMultiGroupKeys`）原样通过、`hitCells` 仍 10、`assertCardWidth`/`cardLines` 每行恒宽断言未放松。

## 被放弃的方案（必填）
- **直接取 52 列（原诉求值）**：实测 `TestRenderUsageReportGroupColumnBudget` 报 `model column cap = 16, want 20`、`TestRenderUsageReportModelColumnTruncation` 的 `very-long-model-nam…` 与 `自定义超长中文模型…` 不再出现——分组列预算只剩 16 列，模型名列上限被迫低于 20，硬约束被破坏。53/54/55 列同样失败（上限 17/18/19）。故回退到最小可行值 56，而非改断言。
- **为挤进 52 列而缩 `hitCells`（10 → 更少）**：命中率胶囊 10 格是任务硬约束（`hitCells` 保持 10），缩它等于牺牲既定不变量，否决。
- **为挤进 52 列而缩 `modelMaxWidth`（20 → 16）或截断 `claude-sonnet-4`**：模型名列上限 20 与「长模型名完整出现」同为硬约束；且会把 `modelMaxWidth` 的断言从 20 改成别的数，属「放宽既有不变量」，否决。
- **为挤进 52 列而删多分组键列 / 改列语义 / 给分组列换窄列宽**：`TestRenderUsageReportMultiGroupKeys`、`TestReportColumnsFillTheTableArea`、`TestRenderUsageReportCardWidth` 的多键与预算不变量必须继续通过，删列或改语义直接破坏它们，否决。
- **两卡不同宽（如 quota 52 / usage 56）**：违背「两卡同宽」约定，并列输出时右侧参差不齐，否决。
- **继续用 60 列不动**：达不到窄屏一屏显示的诉求，否决。

## 来源
- 任务说明（worker 派发）：quota/usage 两卡同步缩窄，胶囊 10 格 + 模型名不截断 + 既有不变量全保留为硬约束；52 列不可行时回退到 52..60 的最小可行宽度。
- 实测证据：`reportWidth`/`cardWidth` 临时置 52/53/54/55 时 `go test ./internal/usage/ -run 'TestRenderUsageReportGroupColumnBudget|TestRenderUsageReportModelColumnTruncation'` 全部 FAIL（`model column cap = 16/17/18/19, want 20`），置 56 时全绿。
