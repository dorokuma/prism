# 架构决策与踩坑笔记规范

本目录记录仓库演进过程中的关键架构决策、技术权衡及踩坑经验。
参考模板：[_template.md](_template.md)

## 何时必须写笔记（满足任一即须写笔记）
触发优先于豁免：单文件 workaround、降级、特判必须记。
1. SQLite schema、索引格式、配置文件格式、对外 API 契约变更
2. 跨两个以上模块或跨仓库
3. 否决了看似更好的方案
4. 临时降级或 workaround 或特判
5. 与 upstream 的故意分歧
6. 性能取舍参数的取值原因

## 何时不用写
- 版本号 bump
- 文案样式
- 行为不变的单文件 bug 修复
- 依赖小版本升级
- 纯补测试

## 命名规则
- 格式：`YYYYMMDD-slug.md`（例如 `20260916-token-usage-sqlite.md`）
- 参考模板：[_template.md](_template.md)

## 维护规矩
- **旧笔记只加 superseded 链接、不改写旧结论**：方案更新时，旧笔记仅在 frontmatter 中更新 `status: superseded` 与 `superseded_by`，并在新笔记中填写 `supersedes`。严禁修改旧笔记的历史事实与旧结论。
- **部分取代只在新笔记里划范围、旧笔记保持 active**：旧笔记结论仍**部分有效**、只有一部分被新笔记取代时，**不整篇标 superseded**——旧笔记保持 `status: active`、`superseded_by: ""`（其原有历史字段不动）；**新笔记的 `supersedes` 亦保持 `""`**。注意 `status: active` **不代表没有取代关系**：部分取代下旧笔记仍为 `active`，取代关系全部由新笔记正文声明：
  1. 新笔记另起一节「**与既有笔记的取代范围（部分取代）**」，逐篇写明**取代了哪些段落 / 哪一句**、**哪些结论仍成立**，并写明被取代的部分**自此失效**还是**仍有效**（仍有效的须说明保留范围）；**若某篇旧笔记的结论整体失效，不得用「部分取代」规避 `status: superseded`**。
  2. **严禁改写旧笔记正文**（含历史数字与旧结论）。即使新结论**回退**了更早笔记的结论（宽度、取值等），也只在新笔记里写明，旧笔记原样保留。
  3. 「**关闭遗留**」同样由**新笔记正文**声明：新笔记可另起一节「**关闭的遗留**」，写清关闭的是哪一项遗留（哪篇旧笔记的哪个节）；**不改旧笔记正文**，**也不动 `_template.md`**。
  4. 既有先例：首例是 `20261003-quota-card-uniform-width.md`（当时只在「决策 / 遗留清单」里声明取代范围，尚无专节）；自 `20261003-quota-metric-gap.md` 起改用上述专节写法，`20261003-quota-countdown-text-and-order.md`、`20261003-quota-row-alignment.md` 同此——上述三篇正文均含「与既有笔记的取代范围（部分取代）」节。
